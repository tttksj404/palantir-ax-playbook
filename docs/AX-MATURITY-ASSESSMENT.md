# AX 성숙도 평가표

> 조직이 AI 기능을 얼마나 많이 만들었는지가 아니라, AI를 안전하게 업무 성과로 반복·확장할 수 있는지를 진단하는 평가표입니다.

## 1. 사용하는 법

1. 각 질문에 대해 현재 상태를 **증거와 함께** 0~4점으로 평가합니다.
2. “계획이 있다”는 점수가 아니라 실제 문서·로그·사용자·지표가 있어야 점수를 줍니다.
3. 한 부서의 점수를 전사 성숙도로 일반화하지 않습니다.
4. 평균보다 가장 낮은 축과 고위험 업무의 점수를 우선 개선합니다.
5. 분기마다 같은 질문으로 재평가하고, 점수 상승보다 증거의 질을 비교합니다.

### 점수 의미

| 점수 | 상태 | 증거 |
|---:|---|---|
| 0 | 없음 | 담당자·정책·프로세스·사례가 없음 |
| 1 | 인식·실험 | 관심·개별 사용·일회성 PoC가 있음 |
| 2 | 반복 시작 | 일부 업무에서 반복 사용·기준선·책임자가 있음 |
| 3 | 제품화 | 운영 서비스·평가·권한·KPI·지원 체계가 있음 |
| 4 | 확장·최적화 | 여러 업무에서 재사용·포트폴리오·지속 개선이 작동 |

## 2. 성숙도 단계

| 단계 | 이름 | 조직의 모습 | 다음 단계의 핵심 |
|---:|---|---|---|
| 0 | Unaware | 비공식 AI 사용이 흩어지고 위험을 모름 | 사용 현황·금지 원칙 파악 |
| 1 | Experiment | 부서별 챗봇·PoC가 생기지만 성과 기준이 약함 | 업무 후보·기준선·책임자 선정 |
| 2 | Repeatable pilot | 몇 개 파일럿이 실제 사용자·평가·로그를 가짐 | 공통 기반·운영·변화관리 표준화 |
| 3 | Productized AX | AI 업무 제품이 운영되고 KPI·승인·지원이 연결됨 | 공통 플랫폼과 도메인 제품팀 확장 |
| 4 | Scaled operating model | 포트폴리오·투자·위험·역량·배포가 반복 가능 | 사업·제품·조직 모델 재창조 |

조직 전체의 단계는 최고 점수나 평균 점수가 아니라 **핵심 업무를 안정적으로 반복할 수 있는 최저 공통 수준**을 함께 보고 판단합니다.

## 4. 점수 계산과 해석

### 4.1 기본 계산

각 축의 질문 점수를 평균 냅니다.

```text
축 점수 = 해당 축 질문 점수 합계 / 질문 수
총점 = 7개 축 점수의 평균
```

단, 다음 하드 게이트가 있으면 총점과 무관하게 해당 업무는 **확장 불가**로 표시합니다.

- 권한이 없는 정보가 노출됨
- 승인 없는 고위험 행동이 실행됨
- 중복 실행·롤백 불가로 운영 피해가 생김
- 누가·무엇을·어떤 근거로 실행했는지 추적 불가
- 개인정보·안전·차별·법적 위험을 식별하지 않음

### 4.2 점수 해석

| 평균 | 해석 | 권장 의사결정 |
|---:|---|---|
| 0.0~0.9 | 시작 전 | 인식·정책·현황 조사를 먼저 함 |
| 1.0~1.9 | 실험 단계 | 작은 읽기·추천 파일럿만 허용 |
| 2.0~2.9 | 반복 파일럿 | 공통 평가·권한·운영 기반에 투자 |
| 3.0~3.5 | 제품화 단계 | 사용자·업무·부서 확장, 제한 행동 검토 |
| 3.6~4.0 | 확장 운영 | 포트폴리오·사업 모델·자율성 재설계 |

### 4.3 진단 예시

```text
전략 3.0 / 업무 1.5 / 데이터 2.5 / 기술 3.0
거버넌스 1.0 / 사람 1.5 / 가치 1.0
```

이 조직은 기술팀의 능력은 있지만, 업무 재설계·거버넌스·가치 측정이 약합니다. 다음 모델을 더 좋은 것으로 바꾸는 것보다, 현업 공동 소유·기준선·권한·승인·KPI를 먼저 보강해야 합니다.

## 7. 평가자 주의사항

- “AI를 많이 사용한다”는 성숙도가 아니라 채택의 한 신호입니다.
- 기술팀이 만든 데모는 제품화 점수의 증거가 아닙니다.
- 정책 문서만 있고 실제 로그·승인·훈련이 없으면 거버넌스 점수를 올리지 않습니다.
- 평균 점수가 높아도 고위험 업무의 하드 게이트 위반은 확장을 막습니다.
- 낮은 점수를 숨기지 말고 다음 투자 순서를 정하는 데 사용합니다.
